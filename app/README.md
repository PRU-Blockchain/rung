# Rung Android app

React Native + Expo **custom development build** (not Expo Go) that buys a
pump.fun token through Rung on **devnet**, with one wallet approval through
Mobile Wallet Adapter (MWA). Started from
[solana-mobile-expo-template](https://github.com/solana-mobile/solana-mobile-expo-template)
v3.0.0 (commit `04cdd54`).

Screens (`src/screens/`, one file each): buy, ladder (live), receipt, not
bought (with retry), history. Logic (`src/flow/`): market and quote, plan and
fees, opening the order (the wallet signs with `signTransactions`, the app
sends; see "Wallet notes" below), running the ladder
(`client`'s `runLadder`), resume after a restart, history. `App.tsx` is a
small state machine that picks the screen.

- The order's session key is generated per buy, kept only in
  `expo-secure-store`, never logged, and deleted once the order is closed and
  the key is empty. On start, an unfinished order is resumed: still open, the
  ladder goes on (after expiry it refunds); already ended, the app reads the
  result from the chain, returns what the key holds and writes the receipt.
- History is in AsyncStorage and opens without a network.

## Layout

- `App.tsx`: screen state machine. Imports `./src/polyfills` first.
- `src/polyfills.ts`: `react-native-get-random-values` and a global `Buffer`.
- `src/utils/useAuthorization.tsx`, `src/utils/useMobileWallet.tsx`: MWA
  authorize / deauthorize / `signTransactions` (fallback
  `signAndSendTransactions`), adapted from the template.
- `src/flow/`: `market.ts`, `plan.ts`, `buy.ts`, `ladder.ts`, `session.ts`,
  `history.ts`, `format.ts`, `connection.ts`.
- `src/screens/`: `BuyScreen`, `LadderScreen`, `ReceiptScreen`,
  `NotBoughtScreen`, `HistoryScreen`, shared `ui.tsx`.
- `src/config.ts`: devnet endpoint (`https://api.devnet.solana.com`). No keys.
- `metro.config.js`: adds `../client` to `watchFolders` and resolves the
  client's package imports (`@solana/web3.js`) from this app's `node_modules`,
  so there is one web3.js copy. `tsconfig.json` maps the same path for `tsc`.

`android/` is generated by `expo prebuild` and is git-ignored (root `.gitignore`).

## Prerequisites

- Node 20+ and npm.
- JDK 17 (`JAVA_HOME`).
- Android SDK with `platforms;android-35`, `build-tools;35.0.0`,
  `ndk;26.1.10909125`, `cmake;3.22.1`, `platform-tools`, `emulator`.
- An emulator or device with an MWA wallet. For testing use Solana Mobile's
  [mock-mwa-wallet](https://github.com/solana-mobile/mock-mwa-wallet)
  (build from its repo root with `gradlew :app:installDebug`; it needs
  `platforms;android-36` and a `local.properties` containing `sdk.dir`).

### Windows: use ASCII paths

Gradle, the JDK and the Android tools break when a path contains non-ASCII
characters (for example a Windows user name like `Buğra`, which ends up in
`%TEMP%` and `~/.gradle`). Keep the repo on an ASCII path (e.g. `C:\dev\rung`)
and set these in every shell that builds (session only, not system-wide):

```powershell
$env:TEMP='C:\Android\tmp'; $env:TMP='C:\Android\tmp'
$env:ANDROID_HOME='C:\Android\Sdk'; $env:ANDROID_SDK_ROOT='C:\Android\Sdk'
$env:GRADLE_USER_HOME='C:\Android\gradle-home'
$env:npm_config_cache='C:\Android\npm-cache'
$env:JAVA_HOME='C:\tools\jdk-17'
# Pass JVM flags to Gradle this way, NOT through JAVA_TOOL_OPTIONS (see Known issues).
$jopts='-Djdk.net.unixdomain.tmpdir=C:\Android\tmp -Djava.io.tmpdir=C:\Android\tmp -Duser.language=en -Duser.country=US -Dfile.encoding=UTF-8'
$env:JAVA_TOOL_OPTIONS=$null; $env:GRADLE_OPTS=$jopts
```

and give the Gradle daemon the same flags on the command line:
`-Dorg.gradle.jvmargs="-Xmx2048m -XX:MaxMetaspaceSize=512m $jopts"`.

## Install and run

```bash
cd app
npm install
npx expo prebuild --platform android      # creates android/
npx expo run:android                       # debug build, install, start Metro
```

Building only the emulator ABI is faster:

```bash
cd android
./gradlew app:assembleDebug -PreactNativeArchitectures=x86_64 --no-daemon "-Dorg.gradle.jvmargs=..."
adb install -r app/build/outputs/apk/debug/app-debug.apk
cd .. && npx expo start --dev-client
```

After the first native build, JS changes only need Metro. Rebuild the APK
after adding a native module or changing `app.json`.

Android package: `com.prublockchain.rung`.

## Testing a price move (devnet, TEST AID)

To see a rung slip or a buy not happen, move the price right after the app's
order opens, from a second devnet wallet:

```bash
npx tsx scripts/devnet-ladder.ts --push-only --mint <MINT> --push-pct 4.5 \
  --wait-order <APP_WALLET_ADDRESS> --keypair <devnet keypair file>
```

It subscribes to the app wallet's order account and buys on pump as soon as a
new order opens. About 4.5% gives "not bought" in Tight mode; about 1.5% makes
the first rung slip and the second fill. Small devnet curves run out of tokens
quickly (the curve completes and every rung fails with pump error 6005).

## Known issues / wallet notes

Observed on the `rung-play35` emulator (Android 15 image) on 2026-11-23, devnet,
Tight mode, 0.01 SOL, token `27wsVth5k9sUpxR9JGQoWbi1EDP4yRU7twNGW6mhqRSK`.
Only these two wallet installs were tried; other versions may behave differently.

**Why sign-then-send.** The wallet only signs (MWA `signTransactions`) and the
app sends the signed bytes itself once it is back in front (`src/flow/buy.ts`).
In earlier runs Phantom's own `signAndSendTransactions` never reached devnet,
and Solflare kept Rung in the background (JS paused) until its success screen
was closed, so orders expired before any rung was tried. Both wallets report
`features: ["solana:signTransactions"]`, so the `signAndSendTransactions`
fallback was not used in these runs.

Problems seen:

- **Phantom asks to Connect on every buy** (see the table). The cause in
  Phantom's log is the unverified app identity, not the token. Verifying it
  presumably needs Digital Asset Links between `rung-drab.vercel.app` and this
  Android app's signing certificate; not tried.
- **"Approval took too long" (`Blockhash not found`)**: the blockhash is read
  before the wallet opens, and a signed-only transaction cannot be refreshed by
  the wallet. When chooser + Connect + reading the sheet took over about a
  minute, the send failed simulation with `Blockhash not found` (once with
  Phantom, once with Solflare). The five buys approved within about 15 to 20
  seconds of tapping Buy all landed. Nothing is sent in that case; the user taps Buy again.
- **First buy, "Network request failed"**: when no account was cached the buy
  connected first and then read the chain while Rung was still in the
  background (Phantom). `App.tsx` now waits for Rung to be in front after
  connecting.

- The public devnet RPC (`api.devnet.solana.com`) rate-limits per IP
  (`429 Connection rate limits exceeded`). web3.js retries with backoff; the
  retries are hidden from the dev-build LogBox but stay in Metro's log. A run
  that still breaks off is refunded by the session key; nothing is retried twice.
- web3.js 1.x `confirmTransaction` sometimes rejects with the transaction's own
  error object (e.g. a slippage `{ InstructionError: [2, { Custom: 6042 }] }`)
  instead of resolving. `client`'s `sendAndConfirm` treats that as an exception,
  which stopped the ladder after the first slipped rung. `src/flow/connection.ts`
  turns it back into a normal result; the proper fix belongs in
  `client/src/ladder.ts`.

Found and fixed:

- **Decimal comma in custom rungs**: "1,5" (a Turkish keyboard's 1.5) was
  read as two rungs, 1% and 5%, with the Buy button on. A comma between two
  digits is now refused with "Use a dot for decimals (1.5) and a comma and space
  between rungs (1, 2, 3)." (`src/flow/plan.ts`). "1,2,3" without spaces is
  refused the same way.
- **Decimal comma in the amount**: "0,01" gave "Enter an amount in SOL.";
  it is now read as 0.01 (`src/flow/format.ts`).
- **Launch suggestion stayed on**: the curve age was read once, so "suggested
  for a token's first two minutes" stayed after the token was two minutes old
  (seen at 144 s). The creation time is kept now and the label goes away at
  120 s (seen live; `src/screens/BuyScreen.tsx`).
- **Connect / Disconnect not shown**: after Disconnect the wallet line stayed,
  and after the first Connect "The button connects your wallet first." stayed,
  until the app was restarted (the saved value was right). The cache is now set
  directly instead of being invalidated (`src/utils/useAuthorization.tsx`).
- **Network off**: a buy showed "Something went wrong: Network request failed";
  now "No network connection. Check it and try again." (`App.tsx`).

Seen, not changed:

- Backgrounding the app right after approving in the wallet (before Rung sent
  the transaction) for about 30 s: the send failed with `Blockhash not found`
  and nothing was sent (same cause as "Approval took too long" above).
- Android Back on the History screen closes the app instead of going back to
  the previous screen (the screen's own Back button works).
- Typing a 44-character address quickly with `adb shell input text` dropped
  characters in the address field; pasting or typing in chunks did not.
- An invalid pasted text shows "This is not a token address."; a completed
  curve "Pool tokens are not supported yet."; a token without a curve (wSOL)
  "This token is not on a pump.fun bonding curve."; a program address and
  another non-token account "This address is not a token."; amounts 0.0009 and 0.51 "Amount must be
  between 0.001 and 0.5 SOL."; an amount above the connected wallet's balance
  "Not enough SOL in the wallet for this buy." (all with the Buy button off).

- `JAVA_TOOL_OPTIONS` breaks the native build: it fails at
  `:expo-modules-core:configureCMakeDebug[x86_64]` with
  `[CXX1210] ... No compatible library found`. AGP runs the prefab CLI and
  treats its stderr as errors; with `JAVA_TOOL_OPTIONS` set, the JVM writes
  `Picked up JAVA_TOOL_OPTIONS: ...` there. Unset it and use `GRADLE_OPTS` /
  `org.gradle.jvmargs` as above.
- Turkish system locale: Gradle prints `BUİLD FAILED`/`BUİLD SUCCESSFUL`, so
  log greps for `BUILD` miss it; `-Duser.language=en` keeps the JVMs in English.
- The first native build is slow (about 20+ minutes on this machine for one ABI).

- The Solana Mobile docs now point to `npm create solana-dapp@latest`; this app
  starts from the standalone expo template repo because it is on web3.js v1.
- The template's README warns that `npm install` can make Metro fail to resolve
  `@solana-mobile/mobile-wallet-adapter-protocol`; with npm 11 it worked here.
- mock-mwa-wallet keeps its key in the Android Keystore with user
  authentication required. On an emulator without a screen lock it shows the
  approval sheet, then crashes on "Connect" with `IllegalStateException: Secure
  lock screen must be enabled to create keys requiring user authentication`,
  and the app shows `java.util.concurrent.CancellationException`.
  To test on an emulator without a screen lock, the test wallet was built with
  `../docs/mock-mwa-wallet-no-lock.patch`; the patch only affects that test
  tool (its Keystore key no longer requires user authentication), never this app.
  Apply it in a mock-mwa-wallet checkout with
  `git apply <path>/mock-mwa-wallet-no-lock.patch`, build with
  `gradlew :app:assembleDebug`, and run `adb uninstall com.solana.mwallet`
  before `adb install` so the old Keystore key is removed. The wallet needs no
  setup of its own: "Public address not configured" only means no key was
  preset in `local.properties`; it generates one on the first `authorize`.
- mock-mwa-wallet reports any failed send (e.g. an unfunded devnet account,
  RPC preflight error `-32002`) to the app as MWA error `-2` "payloads invalid
  for signing", even though it signed the transaction.
- `adb reverse tcp:8081 tcp:8081` is needed before opening the dev client on the
  emulator; open it with
  `adb shell am start -a android.intent.action.VIEW -d "exp+rung://expo-development-client/?url=http%3A%2F%2Flocalhost%3A8081" com.prublockchain.rung`.
- `npm install` warns about install scripts of `bufferutil` / `utf-8-validate`
  (optional Node-only deps of web3.js); they are not needed on Android.
